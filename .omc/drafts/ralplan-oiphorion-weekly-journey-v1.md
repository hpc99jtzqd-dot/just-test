## 1. 요구사항 요약

하루 지도(v0.5)를 "한 주 = 한 판"으로 넓힌다. 매일 처음 넣은 '일어난 시각'이 그날 갈림길(1·2·3선)로 db에 기록되고(자정에 굳음, 빈 날 = 3선), 2선은 그날 모자를, 주 안에서 3선 1번 또는 2선 2번은 그 주 트램펄린을 앗아 간다. 월~토를 트램펄린과 함께 버틴 주만 일요일 산 정상에서 뛰어 다음 맵(5개, 풍경만 다름)으로 간다. 5번째 맵을 넘으면 하얀 문 엔딩 후 2회차. 11월 2일(월) 전은 연습 주. 하루 보기 ↔ 한 주 보기를 오간다. 기록은 아티팩트 `db`(사람별 비공개)에 둔다. C++는 이번 범위 밖.

## 3. RALPLAN-DR 요약

### 원칙 (Principles)
1. **규칙은 순수 함수 하나에서 나온다.** 하루 기록 배열 → 그 주 상태(모자·트램펄린·결과)를 계산하는 결정적 함수. 화면·저장·연출은 그 결과만 읽는다.
2. **기록은 적게, 계산은 매번.** db에는 사실(날짜·일어난 시각·당시 기상 기준·판정 선)과 정산 결과만 둔다. 파생 상태(트램펄린 잃은 날 등)는 저장하지 않는다.
3. **db가 없으면 판정하지 않는다.** 확정(빈 날 3선, 주 정산, 맵 이동)은 db 서버 확정 읽기 뒤에만 일어난다.
4. **기존 렌더 예산을 지킨다.** 풍경 한 번 그리기 + 난쟁이 부분 다시 그리기 구조를 바꾸지 않고, WebGL·움직임 줄이기 없이도 규칙과 한 주 보기가 같다.
5. **한 걸음마다 볼 수 있는 결과.** 단계마다 스크린샷과 시험으로 민이 확인할 수 있게 끊는다.

### 결정 동인 (Decision Drivers, 상위 3)
1. 기기 간 같은 주(휴대폰·노트북) — 정확성
2. WebGL 없음·움직임 줄이기에서도 동작 — 접근성·대체 경로
3. 혼자 유지보수하는 한 장짜리 빌드(외부 라이브러리 없음, 전역 이어 붙이기 함정) — 단순성

### 선택지 (Viable Options)

**결정 A. 한 주 보기를 무엇으로 그리나**
- **A1. HTML/SVG 띠 그림(권장)** — 월~토 6구간 길 + 일요일 정상을 SVG로 그리고, 난쟁이는 기존 `#dwarf` SVG(body.html 23–57행)를 재사용.
  - 장점: WebGL 없을 때 대체가 따로 필요 없다. 셰이더·렌더 예산을 건드리지 않는다. 접근성(버튼·라벨) 쉬움. 휴대폰 세로 배치가 자유롭다.
  - 단점: 3D 풍경과 그림체가 달라진다. 맵 5개 풍경을 SVG 쪽에도 따로 반영해야 한다(색 토큰 공유로 완화).
- **A2. 같은 셰이더로 한 주 지형을 다시 그림** — 카메라를 길 전체로 돌리고, 6구간 표식·떨어진 모자 6개·망가진 트램펄린을 유니폼 배열로 넣는다.
  - 장점: 그림체가 하나. "지도 위 여정" 느낌이 가장 강하다.
  - 단점: 전환마다 전체 다시 그리기(띠 렌더 수 초, SwiftShader에선 더 김). 셰이더 루프·유니폼 추가로 GLSL ES 1.0 제약 부담. WebGL 없을 때 SVG 대체를 결국 따로 만들어야 한다 → A1 작업을 포함한다.
- **A3. 하루 보기 캔버스를 흐린 배경으로 + SVG 띠 겹치기** — A1의 변형.
  - 장점: 그림체 이음이 A1보다 낫다. 비용은 A1과 비슷.
  - 단점: 캔버스 내용이 그날 상태라 한 주 화면과 의미가 섞인다. 맵 바뀐 다음 주 첫날엔 어색.
- 기각 근거: A2는 동인 2·3과 원칙 4에 정면으로 부딪히고 A1을 포함하므로 지배당한다. A3은 A1 위에 나중에 얹을 수 있는 장식이라 별도 선택지로 두지 않고 후속(Follow-up)으로 남긴다.

**결정 B. 규칙 엔진을 어디에 두나**
- **B1. 새 파일 `src/journey.js`(순수, DOM 없음)(권장)** — build.py가 map.js 앞에 이어 붙이고, Node가 `vm`으로 같은 파일을 읽어 시험한다.
  - 장점: 단위 시험 가능. 원칙 1을 코드 구조로 보장.
  - 단점: 파일 하나와 시험 도구가 늘어난다. 전역 이름 충돌(함정 3) 주의.
- **B2. map.js 안에 함수로** — 지금 `decideLine`/`computeLine`(map.js 8–13행)처럼.
  - 장점: 파일 수 그대로.
  - 단점: map.js가 이미 723행이고 DOM·WebGL과 섞여 Node 시험이 어렵다. 주 정산·회차 같은 규칙이 연출 코드와 엉킨다.

**결정 C. 빈 날·정산을 언제 확정하나**
- **C1. 페이지를 열 때 게으르게(권장)** — 열면 서버 확정 읽기 → 지난 빈 날 `auto` 3선 쓰기 → 지난 주들을 순서대로 정산 → `journey` 한 번 쓰기. 같은 입력이면 같은 결과라 두 기기가 겹쳐도 같은 값을 쓴다.
- **C2. 정해진 시각에(자정 타이머)** — 열려 있는 탭이 자정에 씀.
  - 기각: 탭이 닫혀 있으면 아무 일도 없어 결국 C1이 필요하고, 시계 값 타이머 쓰기는 db 지침 위반(F3). 열려 있는 탭에서 자정을 넘기는 경우는 C1을 "날짜가 바뀌면 다시 실행"으로 덮는다(1분 주기 `setInterval`이 이미 있다, map.js 713행 — 쓰기는 날짜가 실제로 바뀐 경우에만).

## 4. 데이터 모델

```
data/users/<uid>/settings            { v:1, wake:"07:30" }
data/users/<uid>/journey             { v:1, map:1..5, lap:1.., weekStart:"YYYY-MM-DD"(진행 중인 주의 월요일),
                                       last:{ weekStart, kept, practice, fromMap, toMap, lapUp, seen:false } | null }
data/users/<uid>/journey/days/<날짜>  { woke:"07:40"|null, wake:"07:30", line:1|2|3, auto:bool, savedAt:ISO }
```
- `<uid>` = `await (await claude.use("user")).id()`. null이면 db 기능 끔(F8과 같은 상태).
- 선언: `capabilities: {db:{}, user:{}}` (기본 규칙으로 `data/users/{self}`는 본인만 읽고 씀. 민은 소유자라 쓰기 가능).
- 브라우저 저장소: 마지막으로 읽은 주를 `dw.cache`로 보조 저장(읽기 전용 표시용). 판정에는 쓰지 않는다.

## 5. 규칙 엔진 (`src/journey.js`)

순수 함수들(모두 서울 날짜 문자열 기준, `Intl.DateTimeFormat('en-CA',{timeZone:'Asia/Seoul'})`):
- `seoulToday(nowMs)`, `mondayOf(date)`, `addDays(date,n)`, `weekNo(monday)` → 연습 주는 0 이하, 1주차 = `2026-11-02`.
- `lineFor(date, woke, wake)` → 요일별 계획(`PLANS`, `LEAVE_AT`)으로 1·2·3선. 지금 `computeLine`(map.js 13행)을 옮겨 이 함수가 원본이 되고 map.js는 이를 부른다.
- `weekState(monday, days, today)` → `{ perDay:[{date,line,hatLost,trampLost,broken,future,auto}], trampLostOn, kept }`
  - 하루씩 차례로: 2선이면 `hatLost`, 2선 누적 2 또는 3선 1이면 그날 `trampLostOn = date`.
  - 그날 이후 `tramp = false`. 3선이면서 잃은 그날 = `feetThenBroken`. 이미 잃은 뒤 3선 = `walk`.
  - 과거인데 기록 없음 → line 3, `auto:true`. 미래 → `future:true`.
- `settle(journey, daysByWeek, today)` → 진행 중인 주가 지났으면 주마다 차례로: `kept && !practice`면 `map+1`, 5에서 넘으면 `map=1, lap+1, ending:true`. 결과 `last.seen=false`. 같은 입력 → 같은 출력(멱등).

## 6. 구현 단계 (단계마다 끊어서 민에게 보여 준다)

**P0. 규칙 엔진과 시험** (화면 변화 없음)
- 새 `src/journey.js`: §5 함수. `computeLine`·`decideLine`을 옮긴다(map.js 8, 13행은 호출만 남김).
- `build.py` 44행 이어 붙이기 순서: `data.js, school.js, journey.js, store.js, scroll.js, map.js, week.js`(함정 7: 선언 순서).
- 새 `tools/journey.test.mjs`: `node:test` + `vm`으로 `school.js`·`journey.js`를 읽어 시험(§8 표의 U1~U12).

**P1. 저장 어댑터 `src/store.js`**
- `Store.init()`: `claude.use` 없음/`null` → `{ok:false}`. 있으면 `user.id()` → 경로 준비.
- `loadWeek(monday)`: `journey` 문서 `get()` + `days` 컬렉션에서 그 주 날짜 범위 쿼리(`where`로 문서 id 범위 대신 `date` 필드를 넣어 `where("date",">=",mon)`).
- `saveToday(woke, wake)`: 오늘(서울) 문서만 `set`. 지난 날짜면 거부(F2). 입력은 `change` 이벤트 + 800ms 모아 쓰기, 같은 문서 쓰기는 한 번에 하나.
- `finalize()`: C1 절차. `fromCache`인 스냅샷으로는 하지 않는다.
- db 오류 코드 처리: `unavailable` 한 번 재시도, `revoked`/`not_granted` → 기록 안 됨 배너, `quota_exceeded` → 배너에 문구.
- 머리말에 저장 상태 칩(`#saveState`: 저장됨 / 저장 중 / 기록 안 됨). body.html 8–15행 갈림길 패널 안.

**P2. 하루 보기를 새 규칙에 맞춤** (map.js)
- 모자 되찾기 제거: `HAT.back`, `reached`, `hatHome`, `arrive`, `pickHatRedraw`의 되찾기 경로(map.js 540–555, 637–640, 693행). `hatLost = 오늘이 2선`.
- 트램펄린: `uDw3.w`(F7) = 그날 트램펄린 있음. 셰이더 `dwarf()`의 등 트램펄린(204–207행)과 발밑 트램펄린(208–212행), 그림자 구(251행)를 이 값으로 끈다.
- `feetMode()`(546행) = `3선 && 그날 잃는 날(feetThenBroken)`. 이미 잃은 뒤 3선은 걷는다(`walkTo` 654행의 `fm` 분기 그대로 false).
- 요일 버튼(body.html 11–13행)은 계획 미리 보기로 남긴다. 단, 이번 주 지난 요일을 고르면 그날 기록된 선을 읽기 전용으로 보여 주고, '오늘 일어난 시각' 입력은 오늘(서울)에만 쓰인다.
- 안내판 마지막 줄(`showInfo` 679–684행) 문구를 새 규칙으로: "모자는 오늘 하루 없다", "트램펄린은 이번 주엔 없다(○요일에 잃음)".

**P3. 한 주 보기** (A1)
- 새 `src/week.js`, `src/week.css`(head.html에 `/*@WEEK_CSS@*/` 자리표시자, 103행 근처).
- 전환 버튼 `#viewToggle`(하루 ↔ 한 주), `aria-pressed`. 한 주 보기 = `#week` 섹션: 6구간 길(구간 색 = 그날 선), 2선 구간엔 떨어진 모자, 잃은 날 구간엔 망가진 트램펄린, 미래는 빈 칸, 일요일 정상 칸.
- 머리에 "연습 주" 또는 "N주째 / 10주", 맵 번호와 회차.
- 휴대폰(400px)에선 세로 띠, 데스크톱에선 가로 띠. 터치 영역 24px 이상(v0.4 기준).

**P4. 일요일 점프와 정산 연출**
- 일요일에 정상 칸을 누르면: 트램펄린 있음 → 튀어 올라 사라졌다가 "다음 주 맵" 미리 보기 / 없음 → 정상에서 발만 구르는 연출 + "같은 맵에서 다시".
- 맵 이동은 월요일 0시 이후 처음 열 때 `settle`이 확정. `last.seen=false`면 "지난 일요일 점프 보기" 버튼이 한 번 뜨고, 보면 `seen:true`로 한 번 쓴다.
- 움직임 줄이기: 이동 없이 결과 그림과 문장으로 바로 보여 준다(motion.css 규칙 추가).

**P5. 맵 5개와 하얀 문 엔딩** (참고 그림 4장을 받은 뒤)
- map.js `shadeGround`(263–321행)·`sky`(163–177행)·`shadeCloud`(322–334행)의 색 상수를 맵 표 `MAPS[0..4]`에서 오는 유니폼 배열(`uPal[k]`, 상수 인덱스로만 접근)로 바꾼다. 지형·칸·길 좌표는 그대로(명세: 하루 구조 같음).
- 맵별 물체 변화는 최소로(예: 맵 4 침엽수 = 나무 SDF 모양 분기 하나). 바뀌는 건 맵이 바뀔 때 한 번 다시 그리기뿐이라 예산은 그대로.
- 엔딩: 5번째 맵 정산 주의 '지난 일요일 점프 보기'에서 난쟁이가 정상(`sunday`)에서 문(`DOOR`, map.js 95행)으로 포물선을 그리며 뛰어 들어간다. `drawDwarf` 부분 다시 그리기를 그대로 쓰되, 포물선이 길면 프레임마다 사각형이 커지므로 프레임 수를 줄인다(초당 30).
- 한 주 보기 SVG 색도 같은 `MAPS` 표에서 가져온다.

**P6. 마무리**
- `CLAUDE.md` 갱신(새 파일, 데이터 모델, 규칙, 함정), 머리말 버전 v0.6(body.html 5행).
- 스크린샷 세트로 민 확인 → 게시(`capabilities:{db:{},user:{}}`).

## 7. 수용 기준 (시험 가능한 형태)

명세의 수용 기준 16개를 시험 이름에 묶는다. U = `tools/journey.test.mjs` 단위, E = `tools/journey-e2e.mjs`(Playwright 1.56, 가짜 `claude.use` + `page.clock`), S = 스크린샷.

| 명세 기준 | 확인 방법 |
|---|---|
| 첫 입력이 그날 기록, 당일 수정, 자정 후 불가 | E1: 10/26 09:00에 입력 → 문서 생김 / 같은 날 고침 → 갱신 / 시계를 10/27 00:01로 → 10/26 입력 칸 읽기 전용, 쓰기 호출 0회 |
| 빈 날 = 3선으로 기록 | U3 + E2: 10/27 기록 없이 10/28 열기 → `days/2026-10-27 {line:3,auto:true}` 한 번 생김 |
| 2선 날 하루 종일 모자 없음, 다음 날 모자 | U4 + S: 2선 날 스크린샷에 모자 없음, 다음 날 1선 스크린샷에 모자 |
| 3선 1번 또는 2선 2번 → 그때부터 주 끝까지 트램펄린 없음 | U5, U6 + E3: 셰이더 유니폼 `uDw3.w`가 0 (테스트 훅 `window.__dw`) |
| 트램펄린 없는 3선 날은 걷는다 | U7 + E4: `feetMode()===false`, 걸음 높이 `hopH`가 걷기 값 |
| 하루 ↔ 한 주 전환 버튼 | E5: `#viewToggle` 클릭 → `#week` 보임, 다시 클릭 → 숨김 |
| 한 주 보기 구간 표시(선·모자·망가진 트램펄린·빈 미래) | E6: 구간 DOM의 `data-line`, `.hat`, `.broken`, `.future` 개수가 엔진 출력과 같다 |
| 일요일 점프 → 다음 맵 / 실패 연출 | E7(성공), E8(실패) |
| 맵·회차가 db에 저장, 다음 주에 그 풍경 | U8 + E9: 정산 후 `journey.map=2`, 새로 열면 `uPal` 값이 MAPS[1] |
| 3선 당일 발밑 트램펄린, 한 주 보기에 망가짐 | U9 + S |
| 정상 칸 눌러 점프, 놓치면 '지난 일요일 점프 보기' 한 번 | E10: 일요일에 안 누르고 월요일 열기 → 버튼 보임 → 누름 → `seen:true` → 다시 열면 안 보임 |
| 5번째 맵 넘으면 엔딩 후 2회차 | U10 + E11 |
| 11/02 전 연습 주, 맵 이동 없음, 'N주째 / 10주' | U11, U12 + E12 |
| 다른 기기에서 같은 기록 | E13: 같은 가짜 저장소를 두 페이지가 공유 → 두 번째 페이지가 같은 주를 그린다 |
| db 없으면 표시, 빈 날 확정 없음 | E14: `claude.use("db")→null` → `#saveState` "기록 안 됨", 쓰기 호출 0회 |
| 움직임 줄이기·WebGL 없음에서도 동작 | E15: `emulateMedia({reducedMotion:'reduce'})`, E16: WebGL 끈 실행(`--disable-webgl`)에서 E5·E6 통과 |

단위 시험 목록(U1~U12): 서울 날짜 경계(UTC 15:00 = 자정), 월요일 계산, 빈 날 3선, 2선 모자, 3선 1번 잃음, 2선 2번 잃음, 잃은 뒤 3선 걷기, 정산 맵 증가, 3선 당일 발밑→망가짐, 5→1 회차 증가, 연습 주 맵 고정, 주 번호(11/02=1주, 1/04=10주).

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 두 기기가 동시에 정산 | `settle`이 결정적이라 둘 다 같은 값을 쓴다. `journey.weekStart`로 멱등 확인 |
| db 캐시(`fromCache`)로 빈 날을 잘못 3선 처리 | 확정은 `get()` 결과로만. 스냅샷 첫 전달은 표시에만 |
| 하루 보기 렌더 예산 증가 | 유니폼 추가는 `uDw3.w`와 `uPal`뿐. 풍경 다시 그리기는 맵이 바뀔 때만 |
| 전역 이름 충돌(함정 3) | 새 파일은 `JR`, `ST`, `WK` 네임스페이스 객체 하나씩만 전역에 둔다 |
| 참고 그림 없음 | P5만 막힌다. P0~P4는 맵 1에서 끝까지 동작 |
| 기기 시간대가 서울이 아님 | 모든 날짜 계산은 `Asia/Seoul`. 기존 `nowId`(map.js 25행)의 기기 시각 사용은 지금처럼 둔다(표시용) |
